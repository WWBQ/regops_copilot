# RegOps 面试自测卷（含答案要点）

> 用法：每个模块先**不看答案**闭卷写。三问自检：
> 1）不看代码能讲清**为什么这么设计**吗？
> 2）改一个参数能**预测**结果吗？
> 3）面试官说「你写错了」，能**判断对不对**吗？
> 三题都「能」→ 简历可硬写；有一题「不能」→ 简历弱化或本周补旋钮实验。
> 答案要点在每节末尾，先折起来别看。

## A. RAG 检索链路（★ 约 14 题）

**A1.** Hybrid 检索里向量和 BM25 各补什么短板？为什么还要 RRF 而不是直接加分？

**A2.** `rag_rrf_k` 默认 60。k **变小**（如 10）时，靠前名次的权重相对变大还是变小？对「一强一弱两路」更敏感还是更平滑？

**A3.** `rag_vector_rrf_weight=2`、`keyword=1`。改成等权 1:1，你预测哪类题 Recall/MRR 会动？为什么现网偏向量？

**A4.** `rag_section_title_boost=3` 是「加分」还是「按名次提前」？为什么不能直接给 RRF 分加权？

**A5.** `rag_max_chunks_per_page`：0 / 1 / 2 三者，谁更容易让少数页占满 top-k？为什么生产选 2 而不是改回 1？

**A6.** `rag_min_score=0.42` 提到 0.9：拒答率、Recall、用户体验各怎么变？降到 0 呢？

**A7.** `hit_passes_relevance_threshold`：向量分 ≥ min_score 放行；**为何 `keyword_score > 0` 也直接放行？** 这是有意还是 bug？把 0.42 提到 0.9 后，关键词命中还会不会被挡住？

**A8.** 精排（reranker）之后，消融里数字题 Recall 为何可能下降？你的应对是继续堆 rerank，还是分流？

**A9.** CiteAcc 0.155 测的是什么？为什么不是产品 KPI？和 Recall@12 为什么可以同时「高召回 + 低 CiteAcc」？

**A10.** 引用（citation）是模型写的还是检索字段透传？最坏失败形态是什么？

**A11.** 部门 ACL：研究岗看不到哪些公司？未登录裁不裁？「泄露率 0」测的是哪一层？Java 未登录路径算不算已测？

**A12.** gold 页如果来自同一套 `doc_chunks`，「用尺子量尺子」风险是什么？你们有没有留出集/披露期之后的干净集？

**A13.** 关掉 rerank（`rag_rerank_enabled=false`），延迟和 Recall 你预测怎么变？P50 大概差一个数量级吗？

**A14.** 追踪一条真实问答：从 `prepare_chat_rag` 到返回 citations，中间必经哪几个函数？（不要求背文件名，要求顺序：收窄文档 → 双路召回 → 融合 → ? → 阈值 → 组上下文）

### A 答案要点

- **A1** 向量抓语义改写；BM25 抓专名/代码/罕见词。分数量纲不同，直接加会偏一路；RRF 按名次融合更稳。
- **A2** 公式约 `1/(k+rank)`：k 小 → 名次差距被放大，更「尖」；k 大更平滑。60 是常见默认。
- **A3** 等权可能抬高关键词题、略伤纯语义题；现网 2:1 因消融里向量贡献主、关键词补专名。
- **A4** 按名次提前 promote 名，不是加分；RRF 与 CE 分不同量纲。
- **A5** 0=不限同页，少数页易占满；1=一页一条，车型清单/详情会丢；2=折中（BUG-012）。
- **A6** 0.9→拒答↑、进 LLM 的少、表面「更安全」但可用性↓；0→低质片段进上下文，幻觉风险↑。
- **A7** 当前实现：关键词 >0 即过阈值，**绕过 min_score**。把 min_score 调到 0.9 **挡不住**关键词命中。属真问题/设计疏漏，面试应主动说。
- **A8** 精排优化「问句-段落相关」，数字题 gold 页未必「像答案」；应对是数字走受控问数，不是无限加 rerank。
- **A9** CiteAcc≈top-k 去重页里 gold 页占比；top-k 大必夹噪。产品看能否支撑回答，不看这个比率。
- **A10** 透传；最坏是检索错页，不是编页码。
- **A11** 研究岗约比亚迪/长城；未登录不裁剪；0 泄露是 Python 检索层黄金集；Java 公开演示路径未同等覆盖。
- **A12** 评测与索引同源会乐观；应有披露期后留出或独立标注。项目文档提过干净留出——能指到就算过。
- **A13** 延迟大降（秒级→百毫秒级），Recall/MRR 通常降（消融：0.76→0.70 量级，以你报告为准）。
- **A14** 大致：`collect_rag_doc_ids`/公司年收窄 → vector+BM25 → RRF →（可选）rerank → section boost → page diversity → threshold → pack citations。

## B. 受控问数（★ 约 8 题）

**B1.** 为什么年报数字不做开放 NL2SQL？EXPLAIN 证明了什么、证明不了什么？

**B2.** `lookup_metric` 只返回哪种 status？`human_review` / 多值冲突怎么处理？

**B3.** 「营业收入」vs「营业总收入」在你们系统里应体现为：一个数、还是质量门拦住？

**B4.** 问数缺公司或指标时发生什么？`pending_asknum` 存什么、TTL、何时清？会不会把旧金额当记忆？

**B5.** `lookup_metric_batch` 和「手算同比」有何不同？

**B6.** Agent 工具表里有没有 `execute_sql`？为什么？

**B7.** 简历若写「Text2SQL + EXPLAIN」错在哪？正确 30 秒怎么说？

**B8.** ROE / 毛利率为什么不让模型算？走哪条路径？

### B 答案要点

- **B1** 能跑的 SQL 可错口径；EXPLAIN 只证语法/计划。
- **B2** 仅 `auto_accepted`；待复核/冲突明说不给数。
- **B3** G1 冲突进 human_review，不静默合并成一个数。
- **B4** metric_clarify；存槽位非金额；~30 分钟；新对话/换题/查完清；每次重查库。
- **B5** 多年份逐条查库并列，不代算比率。
- **B6** 故意不注册。
- **B7** 模块不存在；应说参数化查 `fin_metric`、不写 SQL。
- **B8** 派生路径查组成科目，齐不齐说明，不估数。

## C. 审查工作流 / 「Agent」（★ 约 10 题）

**C1.** LangGraph 审查图上，模型有没有决定「下一步节点」？边是什么形态？

**C2.** 进不进审查图由谁决定？正则大概匹配什么意图？

**C3.** 工具循环（Function Calling）默认何时进入？只挂几个工具？

**C4.** 「7 个工具」为何不能说成「一个 Agent 随时调 7 个」？

**C5.** `interrupt_before=["conclude"]` 挡住什么？确认率黄金集说明什么？

**C6.** Checkpoint 和 Memory 区别？问数 pending 算哪种？

**C7.** 银行 JD 的 planning / tools / memory，你怎么逐条对而不装？

**C8.** 为什么合规场景固定流程可能优于全自主 ReAct？

**C9.** 结论 DTO 里「高风险不得高置信度」在真实 agent 路径是否常触发？为什么？

**C10.** 若补「更 Agent」的最小一步是什么？什么不该动？

### C 答案要点

- **C1** 没有；固定流水线，条件边多是「继续或停」。
- **C2** `intent.py` 规则（两家+结论/管理层等）。
- **C3** 点名「你来选工具」或开放决策意图；5 个只读。
- **C4** 合同 7 个，图与循环分路径挂载。
- **C5** 写结论/草稿前；确认率 1.0=每次都停过人。
- **C6** Checkpoint=任务快照；Memory=跨轮偏好；pending=短槽。
- **C7** tools/action 强；planning 审查路径故意无；memory 薄。
- **C8** 可复现、可审计。
- **C9** 常不触发：模板写死 risk_level=低；规则在 Schema 单测里验。
- **C10** 最多 LLM 意图路由；不把审查图改成自主选边。

## D. 评测方法论（★ 约 8 题）

**D1.** 为什么主要门禁评测刻意不依赖 LLM？

**D2.** `--fail-on-regression` 和「跑个分看看」差在哪？

**D3.** W8 A/B：n=30、Δ=3.3%、p=1.0，为何判定不可信？你的门槛是什么？

**D4.** W8 四策略 0.967 之类数字能当能力宣称吗？为什么？

**D5.** compliance_schema accuracy 1.0 是端到端还是 DTO 单测？

**D6.** 变异测试（放宽/收紧 Schema）用来证明什么？

**D7.** 红队覆盖 Python 工具与否、是否覆盖 Java BFF 完整认证？

**D8.** 坏例记在哪？定位到「检索层还是生成层」为什么重要？

### D 答案要点

- **D1** 稳定、可 CI、不烧钱、可归因。
- **D2** 回归门禁，掉了就拦合并。
- **D3** 样本小、不显著；门槛如 n≥100、Δ≥8pp、p<0.05。
- **D4** 不能，fixture 模拟管线。
- **D5** 纯 Pydantic 单测。
- **D6** 证明评测有鉴别力，不是脚本自嗨。
- **D7** 红队偏 Python；Java 完整链路未同等打。
- **D8** BUG_NOTES；改错层会浪费时间。

- **E6** 项目零 flag；用混元/Spark 作业堆与 GC 经验，并主动区分场景。
