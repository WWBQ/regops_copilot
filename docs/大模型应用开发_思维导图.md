# 大模型应用开发 · 完整思维导图

> 在原九主干上补全二级/三级节点。可整页复制到 ProcessOn。
> 标注「★」= 金融应用岗优先 / 与 RegOps 强相关；「○」= 应知边界；「△」= 可弱化。

```text
大模型应用开发
├── 1. 模型基础原理
│   ├── Transformer ★
│   │   ├── Self-Attention / Multi-Head
│   │   ├── QKV · Softmax · 残差 · LayerNorm
│   │   ├── 位置编码（绝对 / RoPE）
│   │   └── Encoder-Decoder vs Decoder-only
│   ├── Tokenizer 与上下文窗口
│   │   ├── BPE / SentencePiece
│   │   ├── context length · KV Cache 直觉
│   │   └── 中英文分词差异（金融专名）
│   ├── 预训练 / SFT / 对齐 分层 ○
│   │   ├── Pretrain：下一词预测
│   │   ├── SFT：指令跟随
│   │   └── RLHF / DPO：偏好对齐（概念即可）
│   └── 能力边界 ★
│       ├── 幻觉来源（参数记忆 ≠ 事实库）
│       ├── 不会「真正查库」除非挂工具
│       └── 温度 / top_p 对确定性输出的影响
│
├── 2. 开发语言
│   ├── Python ★
│   │   ├── FastAPI / Pydantic / asyncio
│   │   ├── 数据处理：pandas · 清洗脚本
│   │   ├── LLM SDK：OpenAI 兼容协议
│   │   └── 测试：pytest · mock · 黄金集 runner
│   ├── Java ★（金融存量）
│   │   ├── Spring Boot · 鉴权 / RBAC
│   │   ├── 事务 · 乐观锁 · 幂等
│   │   ├── maker-checker 工单
│   │   └── Spring AI / LangChain4j（概念对照即可）
│   └── 协作契约
│       ├── OpenAPI / DTO 边界
│       ├── X-Request-ID · Trace
│       └── 健康检查与降级（AI ≠ 整站）
│
├── 3. 数据工程 ★
│   ├── 数据清洗 ★
│   │   ├── 网页 / SPA 解包
│   │   ├── PDF：页眉页脚 · 双栏 · 跨页表
│   │   ├── 去重：精确哈希 · MinHash-LSH
│   │   └── 质量分层 / 过滤漏斗
│   ├── 文档入库管线 ★
│   │   ├── parse → clean → chunk → embed
│   │   ├── 元数据：公司 · 年份 · 条款 · ACL
│   │   └── 会话附件 vs 永久语料（TTL）
│   ├── 财务事实表 ★（金融特有）
│   │   ├── fin_metric 结构化数字
│   │   ├── 质量门 G1/G2/G3 · auto_accepted
│   │   ├── 口径：合并 / 母公司 · concept 别名
│   │   └── PDF 叙述 ∩ 结构化数字 分家
│   └── 评测数据
│       ├── 黄金集构造与污染防控
│       ├── 留出集 / 披露期切割
│       └── 标注规范与抽检
│
├── 4. Prompt 工程
│   ├── 基础技巧
│   │   ├── 角色 · 约束 · 输出格式
│   │   ├── few-shot / CoT（适用边界）
│   │   └── 拒答与「无证据不编造」★
│   ├── 工程化 ★
│   │   ├── 模板版本化 · pins · 回滚
│   │   ├── 变量与安全（防注入）
│   │   └── A/B：样本量 · 显著性 · 不可信判定
│   └── 硬门不放 Prompt ★

│
├── 5. RAG ★（金融岗第一硬技能）
│   ├── 切分与索引
│   │   ├── chunk_size / overlap
│   │   ├── section_title 元数据
│   │   └── 向量库：pgvector / Milvus …
│   ├── 检索 ★
│   │   ├── Embedding（如 bge-m3）
│   │   ├── 稀疏：BM25 / 关键词
│   │   ├── 融合：RRF（k · 权重）
│   │   ├── 精排：Cross-Encoder
│   │   └── 同页截断 · 节标题 boost · min_score
│   ├── 范围与安全 ★

│   │   ├── 部门 ACL（测清层级）
│   │   └── 低分拒答 · 不进 LLM

│   │   ├── doc_id / page / snippet 透传

│   └── 与问数分流 ★
│       ├── 叙述 / 条款 → RAG
│       └── 报表直读数字 → 受控 lookup（非开放 NL2SQL）
│
├── 6. Agent
```

## 投金融应用岗时的阅读顺序（收敛用）

1. **RAG** → 2. **数据工程（含事实表）** → 3. **工程化（评测+安全）** → 4. **Agent（讲清 Workflow 取舍）** → 5. **Prompt 工程化** → 6. **Java 边界** → 其余（微调/推理/原理）按 JD 加分补，不抢主线。

## 与 RegOps 的对应（答辩锚点）

| 导图节点 | 项目证据 |
|---|---|
| RAG | Hybrid + RRF + rerank · 黄金集消融 |
| 数据工程 | PDF 清洗 · fin_metric · G1/G2/G3 |
| 问数分流 | asknum 参数化 · 不做开放 NL2SQL |
| Agent | 固定审查图 + FC 循环 + HITL |
| 工程化 | 双栈 · 回归门禁 · 红队 |
| 微调 | CantoFin QLoRA（加分，非主线） |
| 推理 | vLLM / API · Compose |
