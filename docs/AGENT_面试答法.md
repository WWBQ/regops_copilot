# Agent 部分面试答法（可背）

> 性质：能力缺口的**讲法**，不是可信度造假。审查图是固定 Workflow，文档已诚实；本页把「为什么不强行做成自主 Agent」讲成加分。

---

## 30 秒主答（先背这段）

审查主路径我做成了 **LangGraph 固定工作流**，不是模型动态规划的 Agent。

进不进图由规则意图决定（两家公司 + 管理层/结论）；进图后顺序硬编码：
`classify → list_scope → compare → verify → rag → conclude`，边上只有「下一步或停」。
模型**不决定下一步做什么**。

这是有意取舍：合规场景里，同一类问题必须走出同一条**可复现、可审计**的路径。
若让模型自选顺序，出了结论就难复盘。自主性和可审计性在这里是矛盾的，我选了可审计性。

真正有工具自选的是另一条：**Function Calling 工具循环**——真调 `tools=`、共享 registry、预算硬约束，
但只挂 5 个只读工具，且默认要用户点名或命中开放决策意图。
写路径一律 `interrupt_before` 人工确认，不注册 `execute_sql`。

对照银行 JD：tools use / action 是我的强项；planning 在审查路径上故意不做；
memory 只有 Checkpoint 和问数短槽，没有长期语义记忆——我会主动说清边界。

## 追问预案

### 「那你简历为什么写 Agent / 智能体？」

产品上是「合规审查助手」；技术上应拆成三块：固定审查图、可选工具循环、Java maker-checker。
若写「智能体」容易被理解成 ReAct 自主规划——口述要立刻补一句「审查路径是固定图」。

### 「Agent 在哪里决定下一步？」

审查路径：**它不决定**，边是代码写死的。开放工具循环：模型选**调哪个只读工具**，不选「要不要出合规结论落库」。

### 「7 个工具怎么理解？」

工具合同 7 个。审查图可用只读 5 个 + 写路径 2 个；开放循环只挂只读 5 个。
说「按路径挂载」，不说「一个 Agent 随时调 7 个」。

### 「Checkpoint 算 memory 吗？」

不算长期 memory。Checkpoint = 这一次图跑到哪、已查出的数，用来暂停/恢复，TTL 24h。
问数 pending = 未填完的槽，约 30 分钟。数字每次重查 `fin_metric`，不把旧回答当记忆。

### 「为什么不做成全自主 Agent 更酷？」

酷的代价是不可审计。金融里更贵的是「同题不同路径、无法复盘」。
我把自主性限制在开放查询；监管相关路径用固定图 + 人确认。

### 「planning / replanning / 多智能体你会吗？」

现状：审查无动态 planning、无失败换策略的 replanning、无多 Agent 委派。
若补，最小一步是 **LLM 意图路由**（替换部分正则），审查图仍保持固定边——
先补「该不该进哪条路径」的判断，不把监管路径改成全自主。

### 「和上海银行 JD 四项怎么对？」

| JD | 我对法 |
|---|---|
| tools use | 强：合同、FC、白名单、不挂 execute_sql |
| action | 有：真执行、回填、预算 |
| planning | 审查路径故意固定；开放路径有工具选择 |
| memory | 薄：Checkpoint + pending；无语义长期记忆 |

## 禁止说的话

- 「模型自己规划审查步骤」
- 「完整自主 Agent」
- 「7 个工具随时调用」
- 「有长期记忆 / Memory」
- 把 Checkpoint 说成跨会话偏好记忆
