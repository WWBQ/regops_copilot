## 一、配置与部署

### Q1：`.env` 放哪？Python 在 `python-ai/` 怎么读到根目录的配置？

**30 秒答：** Monorepo 惯例把 `.env` 放在项目根（与 `compose.yaml` 同级），Docker、Java、Python 共用。Python 不会自动向上找文件，要在 `config.py` 用 `Path(__file__)` 定位到 `regops_copilot/.env`。本地开发读文件；容器里通常只有环境变量，代码仍用 `pydantic-settings`，不用改逻辑。

**项目证据：** `python-ai/app/config.py` · `ROOT_DIR` · `.env.example`

**追问准备：** 环境变量优先级高于 `.env`；终端 `export` 过旧 Key 会覆盖文件。

**踩坑：** 在 `python-ai/` 里 `cp .env.example .env` 读不到；改 `.env` 后旧 Key 仍生效 → 查 `export` + 重启。

---

### Q2：`@lru_cache` 在 `get_settings()` 上是干什么的？生产能用吗？

**30 秒答：** 缓存应用级 `Settings` 单例，避免每次请求重复读环境变量。生产可用——每个 Pod 启动读一次 Secret/环境变量后缓存。改配置需滚动重启 Pod，或去掉永久缓存改用 TTL/配置中心。缓存的是 **DB URL、API Key**，不是用户级数据。

**项目证据：** `python-ai/app/config.py` · `get_settings()`

**追问准备：** 测试里 `get_settings.cache_clear()`；多 worker 各有一份缓存，内容应相同。

**踩坑：** 改 `.env` 不重启 uvicorn → 仍用旧 Settings。

---

### Q3：生产环境换 API Key 或加新模型，不想影响用户怎么办？

**30 秒答：** 三层答案：① 多副本 **滚动重启** + Secret 轮换 + 双 Key 并存窗口（最常见，用户无整体停机）；② 去掉 `@lru_cache`，Settings **TTL 重载**（如 60s）；③ 模型注册表放 DB + Admin API，factory 按版本重建 Client。用户隔离不靠多份 Settings，靠 Token 和 `dept_acl`。

**项目证据：** `models/factory.py` · W9 Compose/K8s · W7 RBAC

**追问准备：** 为何不为每个用户 cache 一份 Settings？——错误方向，应用配置全局共享。

---

### Q4：Docker 部署时 Python 和 Java 放一个容器还是分开？

**30 秒答：** **分开**，各一个容器（web / java-service / python-ai / db），Compose 组网。一个容器一个主进程，独立扩缩、独立发版。容器间用服务名通信（`http://python-ai:8000`），不用 `localhost`。密钥用 `environment` 或 `env_file` 注入，**不要**打进镜像层。

**项目证据：** `compose.yaml` · 学习系统架构图 W9

**追问准备：** JDBC URL vs Python `DATABASE_URL` 格式不同，密码可共用。

---

### Q5：配置「注入」后代码怎么读？

**30 秒答：** 注入 = 写进进程环境变量。Python 用 `pydantic-settings` 自动映射 `DEEPSEEK_API_KEY` → `deepseek_api_key`；Java 用 `application.yaml` 的 `${VAR}`。优先级：系统环境变量 > `.env` 文件 > 代码默认值。

**项目证据：** `config.py` · `compose.yaml` · `.env.example`

## 二、Python / FastAPI / 模型调用

### Q6：FastAPI 和 uvicorn 分别干什么？

**30 秒答：** FastAPI 是框架（路由、Schema、依赖注入）；uvicorn 是 ASGI 服务器（监听端口、把 HTTP 交给 FastAPI）。开发：`uvicorn app.main:app --reload`。`--reload` 只监听代码变更，**不**监听 `.env`。

**项目证据：** `app/main.py` · 启动命令 port 8000

**项目证据：** `app/models/base.py` · `deepseek.py` · `qwen.py` · `factory.py`

### Q9：为什么有 `chat()` 和 `chat_with_usage()` 两个方法？

**项目证据：** `base.py` · `docs/model_selection_w1.md`（待写）

### Q20：为什么要 `APIRouter`？不用可以吗？

**30 秒答：** **可以不用**——全写在 `main.py` 里 `@app.get` / `@app.post` 也能跑。用 `APIRouter` 是 **分模块**：每个功能一个文件（health/chat/models），`main.py` 只 `include_router` 组装。好处：文件短、好找、多人少冲突、一组路由可统一 `prefix`/`tags`。W1 三个接口不拆也能活，RegOps 后面 ingest/RAG/Agent 多了必须拆。

**项目证据：** `app/main.py` · `app/api/health.py` · `chat.py` · `models.py`

**追问准备：** `tags=["health"]` 只影响 Swagger 文档分组，不影响 URL。

---

### Q21：`prefix="/chat"` 是什么？为什么 health 没前缀？

**30 秒答：** `prefix` 给 **整组路由** 统一加路径前缀。`chat`：`prefix="/chat"` + `@router.post("")` → `POST /chat`；`models` 同理 `prefix="/models"`。**health 没 prefix**，路径直接写在 `@router.get("/health")`——W1 风格不统一，两种写法 **等价**。用 prefix 的好处：同一模块多个子路由时不用重复写前缀，如以后 `/chat/stream`。

**对照：**

| 文件 | 写法 | 最终 URL |
|------|------|----------|
| `health.py` | 无 prefix，`@router.get("/health")` | `GET /health` |
| `chat.py` | `prefix="/chat"` + `@router.post("")` | `POST /chat` |
| `models.py` | `prefix="/models"` + `@router.get("")` | `GET /models` |

**项目证据：** `api/health.py` · `api/chat.py` · `api/models.py`

---

### Q22：`response_model=ChatResponse` 干什么？

**30 秒答：** 声明 **响应 JSON 的结构**：FastAPI 按 `ChatResponse` 校验/序列化返回值，Swagger `/docs` 自动生成响应字段文档；多写字段会被过滤。和入参对称：`ChatRequest` 校验 body，`ChatResponse` 约束 response。`disclaimer` 有默认值，return 里不写也会出现在 JSON 里。

**项目证据：** `api/chat.py` · `schemas/chat.py`（`reply` / `model` / `disclaimer`）

**追问准备：** `-> ChatResponse` 是 Python 类型提示给 IDE；运行时主要靠 `response_model`。

---

### Q23：GET 和 POST 怎么选？

**30 秒答：** **GET = 读**（查询、无副作用）：参数在 URL/query，无 body，幂等。项目里 `GET /health`、`GET /models`。**POST = 提交/执行**（有 body、可能有副作用）：数据放 JSON body。`/chat` 用 POST 因为 message 可能很长、不应进 URL/日志，且每次调用 LLM 有成本——语义是「执行对话」不是「取静态资源」。

**对照：**

| 接口 | 方法 | 原因 |
|------|------|------|
| `/health` | GET | 只读存活状态 |
| `/models` | GET | 只读模型列表 |
| `/chat` | POST | body 传 message，触发 LLM |

**项目证据：** `api/health.py` · `api/models.py` · `api/chat.py`

**踩坑：** 用 `GET /chat?message=...` 能跑但不规范——URL 长度、敏感信息、语义都不对。

## 二点五、日志与可观测性（W1 已做）

### Q27：`logger = logging.getLogger(__name__)` 干什么？和 `print` 有什么区别？

**30 秒答：** 在当前模块占 logging 树上一个节点，名字是模块路径（如 `app.models.deepseek`）。打 `logger.info/warning/error` 会沿树 **propagate** 到 root，用统一格式输出。比 `print` 强在：分级（INFO/ERROR）、带来源 `[app.xxx]`、生产可关 DEBUG、可接日志平台；`print` 无法按模块过滤，也不进标准日志链路。

**项目证据：** `deepseek.py` · `chat.py` · `parser.py` · `logging_config.py`

**追问准备：** 默认 propagate=True；子 logger 通常不自己加 handler。

**踩坑：** 只定义 `logger` 从不 `logger.info` → 终端没有任何业务日志（以前 timeout 只 `raise` 不打 log）。

---

### Q28：为什么 `raise ModelTimeoutError(...)` 不会自动打日志？

**30 秒答：** **`raise` 和 `logger` 是两条线**：`raise` 中断流程、把错误交给上层（最终变 HTTP 502）；`logger.error` 才是记一条日志。必须 **既 log 又 raise**——log 给运维/排障，raise 给 API 返回错误。uvicorn 的 `POST /chat 502` 是访问日志，不含 `DeepSeek request timed out` 业务详情。

**项目证据：** `deepseek.py`（`logger.error` + `raise ModelTimeoutError`）· `chat.py`（`logger.warning` + `HTTPException 502`）

**踩坑：** 以为抛异常会自动打印堆栈到业务日志——只有未捕获异常才打 traceback；被 `except ModelError` 吃掉后，要靠手写 logger。

---

### Q29：`setup_logging()` 只在 `main.py` 调一次，其他文件怎么统一格式？

**30 秒答：** 全进程 **共用一棵 logging 树**。`setup_logging()` 给 **root logger** 配 `StreamHandler` + `Formatter`；各文件 `getLogger(__name__)` 只是挂子节点，**默认向上 propagate 到 root**，所以格式一致。其他文件 **不必 import setup_logging**，只 `import logging` 即可。类比：给整栋楼装总电表，各户用电走同一套计费格式。

**项目证据：** `logging_config.py` · `main.py`（`lifespan` 里 `setup_logging()`）

**追问准备：** `if root.handlers: return` 防 uvicorn `--reload` 重复加 handler。

**踩坑：** pytest 直接 import 函数、不跑 lifespan → root 可能无 handler，业务 log 不显示。

---

### Q30：`lifespan` 里调 `setup_logging` 为什么，不写在文件顶层？

**30 秒答：** `lifespan` 是 FastAPI **启动/关闭钩子**：`yield` 前做初始化（配日志、预热），`yield` 后做清理（关连接池）。比写在 `main.py` 顶层好：**只有 uvicorn 真正拉起服务时才配日志**；被 import（测试）时不副作用。和「改 `.env` 要重启」一样——日志配置跟进程生命周期绑定。

**项目证据：** `main.py` · `@asynccontextmanager` · `FastAPI(lifespan=lifespan)`

**追问准备：** 以后可在 `yield` 前 `app.state.http_client = ...`，`yield` 后 `aclose()`。

---

### Q31：日志该打在哪一层？deepseek / chat / parser 怎么分工？

**30 秒答：** **Adapter 层**（`deepseek.py`）记模型细节：超时、429、token、延迟；**API 层**（`chat.py`）记 HTTP 语义：`POST /chat ok` 或 `model error`；**ingest 层**（`parser.py`）记文件级：`parse_pdf start/ok/fail`。库异常在 adapter **翻译**成 `ModelError` 并 `logger.error`；HTTP 状态码在 API 层定 502。**不要**在 schema 层打 log；**不要**打 API Key。

**项目证据：** `deepseek.py` · `chat.py` · `ingest/parser.py` · `factory.py`（Key 缺失 `logger.error`）

**踩坑：** 401/timeout 只在 deepseek 打 log、chat 不打 → 访问日志只有 502，缺 API 层上下文；两层都打是刻意的。

## 二点六、Schema 与合规 DTO（W1 Day 2）

### Q32：`compliance.py` / `ComplianceConclusion` 是干什么的？

**30 秒答：** 定义 **合规审查结论** 的 Pydantic 模型（DTO）：`conclusion`、`risk_level`（低/中/高）、`clause_refs`（条款编号）、`evidence_quotes`、`confidence`。W1 **还没接 API**，只做 Schema + `test_schemas.py` 单测 + **20 样例统计报告**（`compliance_schema` 评测任务）。将来 LLM 结构化输出 → 校验 → Java maker-checker 复核（W9）。和 `schemas/chat.py` 一样：**先定数据结构，再写路由**。

**项目证据：** `app/schemas/compliance.py` · `tests/test_schemas.py` · `eval/golden/compliance_schema_20.json` · W1 Day 2 清单

**追问准备：** 合规结论必须能追溯到条款；高风险不允许 confidence > 0.95。

**踩坑：** 以为 W1 就要 `/compliance` 接口——当前只练 Validator，前端「合规复核」是 W9+ 占位。

### Q33：测试非法 Schema 为什么用 `with pytest.raises(ValidationError)` 不用 try/except？

**30 秒答：** **`pytest.raises` 是测试专用断言**：块内必须抛指定异常，没抛或抛错类型 → 自动失败。`try/except` 是生产代码「抓住错误继续跑」；测试里还要手写 `assert False`，易漏。Pydantic 校验失败统一抛 **`ValidationError`**，包住 `field_validator` / `model_validator` 里的 `ValueError`。

**项目证据：** `tests/test_schemas.py` · `@pytest.mark.parametrize` 五组坏数据

**对照：**

| | `try/except`（生产） | `pytest.raises`（测试） |
|---|---------------------|-------------------------|
| 意图 | 出了错怎么办 | **期望**这里出错 |
| 没抛异常 | 继续执行 | 测试失败 |

**踩坑：** 只测合法用例不测非法——坏 JSON 进库才发现规则没 enforce。

---

### Q34：`@field_validator` 为什么要 `@classmethod`，`@model_validator` 为什么用 `self`？

**30 秒答：** Pydantic **在创建实例的过程中分阶段校验**，不是先 `new` 空对象再填字段。**`field_validator` 只处理单个字段**，此时尚无完整 `self`，只有 `(cls, value)` → `@classmethod`，**return 清洗后的字段值**。**`model_validator(mode="after")` 在实例字段都赋好后**才跑，要看 `risk_level` + `confidence` 组合 → 用 `self`，**return self**。

**构造顺序（口述用）：**

```text
Field/Literal 规则 → field_validator(clause_refs 去空) → 拼成实例 → model_validator(after) 高风险+置信度
```

**对照：**

| | `field_validator` | `model_validator(after)` |
|---|-------------------|---------------------------|
| 装饰 | `@classmethod` | 实例方法 |
| 参数 | `cls, value` | `self` |
| 何时 | 字段入库**前** | 实例建**后** |
| 返回 | 该字段最终值 | 整个对象（可改字段） |
| 典型 | `clause_refs` strip、至少 1 条 | 高风险 confidence ≤ 0.95 |

**追问准备：** `clause_refs` 规则**也能**写在 `model_validator(after)` 里用 `self.clause_refs` 校验——能跑，但单字段清洗更 idiomatic 用 `field_validator`。不是「high 要两个参数所以 field 不能用实例」，而是 **field 阶段本来就没有完整实例**；high 必须等两字段都确定，故只能 `after`。

**项目证据：** `compliance.py` · `clause_refs_must_be_non_empty` · `high_risk_should_not_be_overconfident` · [Pydantic 学习指南](./pydantic_学习指南.html)

### Q35：已经有 `test_schemas.py` 了，为什么还要一份 20 样例评测报告？

**30 秒答：** 两者目的不同。**pytest 是门禁**，只回答「过 / 不过」，红了就阻断合并；**评测报告是度量**，输出可归因、可比较的指标：`accuracy`、**`false_accept_rate`（误放行率）**、`false_reject_rate`、`rule_hit_rate`，并按规则列出失败样例。合规场景真正要盯的是**误放行**——非法结论被放过一条就是事故，而 pytest 的绿灯不会告诉你这个比例是多少、退化了多少。报告落盘到 `eval/reports/compliance_schema/<时间戳>/`，可跨版本对比。

**三层判定（为什么不只看 accuracy）：**

| 层 | 判什么 | 防的问题 |
|---|--------|----------|
| `decision_correct` | 放行/拒绝方向对不对 | 基础正确性 |
| `rule_matched` | 拒绝理由是否命中预期约束 | **「拒对了但理由是另一条规则」的假通过** |
| `normalized_ok` | 字段清洗结果对不对（如 `clause_refs` 去空白） | 静默的规范化退化 |

**追问准备（关键）：** 「一份 100% 通过的报告怎么证明它有鉴别力？」——加**变异测试**：把 `ComplianceConclusion` 换成故意放宽的模型（去掉所有约束），断言 `false_accept_rate ≥ 0.9`；再换成过严的模型（只收「低」风险），断言 `false_reject > 0`。跑不出来说明是脚本在自说自话。见 `tests/test_compliance_schema_eval.py`。

**项目证据：** `app/eval/compliance_schema_runner.py` · `eval/run_compliance_schema.py --fail-on-regression` · `eval/scripts/build_compliance_schema_golden.py`（长度边界样例字符级精确，故脚本生成而非手写 JSON）

**踩坑：** 第一版把「未声明清洗断言」的样例也算进 `normalization_checked`，10 个合法样例全被计为「已检查通过」，指标虚高——实际只有 2 条声明了断言。未声明应返回 `None` 不计入分母。

### Q36：公开金融基准和自建 30 条黄金集怎么分工？FinanceBench 很高能写简历吗？

**30 秒答：** 公开基准（CFLUE / FinEval / FinQA / FinanceBench / FinMTEB）用来**看题型和别人怎么标注**；日常回归、防污染用**自建近期披露集**。CFLUE 刷高只说明会做中文金融选择题，说明不了「能从比亚迪 2024 年报第几页把营收找对」。FinanceBench 开源只有 150 条、英文 10-K、CC-BY-NC、全文 1 万条不开放——简历写「建立了评测与对标流程、对照过检索仍会胡答的失败模式」，**不写超过 GPT-4 百分之几**。

**项目证据：** [`docs/benchmarks/README.md`](./benchmarks/README.md) · `eval/golden/w1_chat_30.json` · `eval/scripts/download_cflue.sh`（只打印链接，不提交原数据）

**追问准备：** CFLUE 数据是 CC BY-NC-SA，代码才是 MIT——商用和再分发看数据集那一层。FinMTEB 的 64 集许可各不相同。

## 三、测试

### Q10：Mock 是什么？为什么 pytest 不断网也能测 `/chat`？

### Q11：`@pytest.mark.anyio` 是什么？还有哪些常见 mark？

**30 秒答：** 标记异步测试，anyio 启动 asyncio 事件循环跑 `async def test_*`。配合 `anyio_backend` fixture 指定 asyncio。其他常用：`@pytest.mark.parametrize`（多组输入）、`skip`/`skipif`、`xfail`。fixture（如 `client`）是准备环境，不是 mark。

**项目证据：** `tests/test_api.py` · `tests/test_schemas.py` · `pytest.ini`（`asyncio_mode=auto`）

### Q12：为什么测试放 `tests/` 而不是 `app/tests/`？`pytest.ini` 干什么？

**30 秒答：** `app/tests/` 会导致 `from app.config` 包名冲突。测试与 `app` 同级，用 `pytest.ini` 的 `pythonpath=.` 让 pytest 找到 `app` 包。`testpaths=tests` 指定只扫测试目录。

**项目证据：** `python-ai/pytest.ini` · `python-ai/tests/`

### Q13：`app/__init__.py` 为什么需要？

**30 秒答：** 标记 `app` 为 Python 包，使 `from app.config import ...` 和 pytest 导入稳定。可以是空文件。子包 `models/`、`schemas/` 同理。

**项目证据：** `app/__init__.py`

### Q19：为什么不直接传 `FakeLLMClient()`？什么时候可以直接传参？

**30 秒答：** 看测什么。**测 HTTP**（`client.post("/chat")`）时，是 FastAPI 内部调 `chat()`，测试代码碰不到参数列表，只能在 Depends 注入层换假的：`app.dependency_overrides[get_llm_client_dep] = lambda: FakeLLMClient()`——意思是「凡是 `Depends(get_llm_client_dep)` 的地方，别调原函数，改返回 `FakeLLMClient()`」。**测普通业务函数**（无 HTTP）时，直接 `await summarize(..., FakeLLMClient())` 即可，更简单纯粹。两种都对，层次不同：前者测整条 API 链路，后者只测函数逻辑。

**对照：**

| 测什么 | 怎么调 | 怎么传 Fake |
|--------|--------|-------------|
| `POST /chat` 接口 | `client.post("/chat", ...)` | `dependency_overrides` |
| `chat()` / `summarize()` 等业务函数 | `await chat(...)` / `await summarize(...)` | 直接当参数传 |

**项目证据：** `tests/test_api.py` · `api/chat.py`（`Depends(get_llm_client_dep)`）· `api/deps.py`

**追问准备：** override 是替换整个依赖函数，原 `get_llm_client_dep` 不会执行；测完必须 `dependency_overrides.clear()` 避免污染后续用例。

**踩坑：** 以为 HTTP 测试也能在 JSON 里传 `client=FakeLLMClient()`——HTTP 没有这个入口，只有服务端 Depends 能注入。

## 四、数据库与 RAG（W1 已铺 / W2 主线）

### Q14：为什么选 pgvector 而不是 Milvus？

**30 秒答：** RegOps 阶段数据量万~百万级，业务表（fin_metric、工单）和向量同库，事务一致、运维简单。pgvector = PostgreSQL 扩展，不是单独服务。Milvus 适合亿级独立向量集群——面试能说取舍，作品集先用 pgvector。

**项目证据：** `compose.yaml`（`pgvector/pgvector:pg16`）· `docs/sql/init_pgvector.sql`

**追问准备：** `vector(1024)` 维度必须和 Embedding 模型一致。

### Q15：W2 文档入库的数据流怎么说？

**30 秒答：** PDF → parse → clean（NOISE_PATTERNS）→ 抽 **Financial Fact** → **G1 金额一致性 / G2 勾稽 / G3 证据坐标** 三道门 → 通过才进 fin_metric → chunk+embed → RAG。不比整页数字集合，只比同一金融事实；冲突进 human_review，不静默挑数。

**项目证据：** [W2 数据流图](./W2_引导式手写清单.html#flow) · [INGEST_VALIDATION.md](./INGEST_VALIDATION.md) · `app/ingest/`（待建）

**踩坑：** 万元/亿元换算；ROE 直读报表勿手算；缺 bbox 的关键金额不得 auto_accept。

### Q26：PDF 和 XBRL 怎么分工？RegOps 要不要接 XBRL？

**30 秒答：** **PDF** = 人读版面，适合 RAG 叙述、制度条款、解析后 chunk；噪声多（页眉页脚），数字抽取易错。**XBRL** = 机读结构化披露，每个 fact 带标准 tag + taxonomy，数字 **口径清晰、可跨公司比较**，适合 `fin_metric` 入库和 W4 问数。RegOps W2 **主线仍是 PDF**（巨潮年报）；W4 可在 `fin_metric` 预留 `xbrl_tag`/`context`；**有 XBRL 则数字以结构化源为准，PDF 做交叉验证和 RAG**，不让 LLM 从扫描 PDF 硬猜净利润/ROE。

**对照：**

| | PDF | XBRL |
|---|-----|------|
| 用途 | RAG、条款引用、叙述 | 三表数字、指标、问数 |
| 解析 | Docling + NOISE_PATTERNS | 解析 instance XML |
| W2 | 必做 | 扩展（可选） |

**项目证据：** W2 ingest · `fin_metric`（F10 JSON 过 G1/G2/G3 入库）· [XBRL 标准介绍](https://www.xbrl.org/the-standard/what/what-is-xbrl/)

**追问准备：** 页眉页脚优先规则/版面块分类（标注口径），不为噪声单独微调 LLM。

**个人证据（可口述）：** 工作中参与 PDF 版面块分类标注；上游微调版面模型，你负责口径与质检——迁移到 `NOISE_PATTERNS.md` 页眉页脚类。

### Q37：年报问数为什么不做成开放 Text2SQL / NL2SQL Agent？

**30 秒答：** 电商数仓表多、要 JOIN，开放 NL2SQL（召回 schema → 模型生成 SQL → EXPLAIN → 执行）说得通。年报数字更怕**一条能跑的 SQL 查出错误口径**（营业收入 vs 营业总收入、合并 vs 母公司、致辞约数 vs 报表行）。RegOps 数字走已过 **G1/G2/G3** 的 `fin_metric`，只读 `auto_accepted`；LLM **不写 SQL、不手算 ROE**。叙述、条款、因果走 Hybrid RAG。多步任务才上 Agent，Agent 只编排这些工具。

**项目证据：** `fin_metric` + `/ops/quality/gates` · `rag/service.py`（`should_use_rag`）· [ACCOUNTING_RULES.md](./ACCOUNTING_RULES.md) · [DATA_SOURCES.md](./DATA_SOURCES.md)（F10 结构化源，不从 PDF 猜数）

**追问准备：** 表/维度变多可以加 schema 召回，执行仍是白名单 + 只读 + 仅 `SELECT`；开放「校正 SQL 再跑」不进年报主路径。EXPLAIN 只证明语法能跑，不证明口径对。

**踩坑：** 把教学向数仓问数贬成「不工程化」——元数据召回、EXPLAIN、流式进度在 **BI 问数**里是对的，错的是拿它当财报数字主路径。

---

### Q38：开放 NL2SQL 和受控问数，面试怎么对比？

**30 秒答：** 先承认两套都能跑，再收到达域。一条是 **NL2SQL Data Agent**：召回表/指标/取值，生成 SQL，EXPLAIN 后再查数仓。另一条是 **受控查数 + 必要时再编排**：数字走事实表，叙述走 RAG，多步才上图。电商数仓倾向第一条；年报/合规选第二条。不要说某门课「不行」，说「典型开放 Text2SQL」和「金融受控问数」。

**对照：**

| | 开放 NL2SQL（教学问数） | RegOps（年报/合规） |
|---|---|---|
| 核心问题 | 表多、要 JOIN、业务自助查 | 数字对、口径对、能追溯 |
| 编排 | 整条问数都在 LangGraph 里 | `/chat` 先路由；图只给多步任务 |
| 数字从哪来 | 模型生成的 SQL | `fin_metric` 且 `status=auto_accepted` |
| 失败怎么处理 | EXPLAIN 不过 → 校正 SQL 再跑 | 对不上或 `human_review` 就停，不静默改写 |
| 错了像什么 | 聚合错、JOIN 错 | 口径错、报表和致辞混成一个数 |

**收口一句：** 金融里更贵的不是 SQL 写不出来，而是**能跑的 SQL 查出错误口径**，所以不把生成 SQL 当主路径。

**现状怎么说（避免把规划说成已落地）：**

> 这是设计结论。线上已有 RAG、质量门和 `fin_metric`；问数按受控 lookup 接 `/chat`，Agent 只编排已有工具。图若尚未接线，就明说「单轮问答不需要图，所以还没上」。

**追问准备：**

- **表多了还不用 Text2SQL？** 召回可以上，执行仍白名单；校正循环不进年报数字。
- **那要 Agent 干什么？** 单问营收不用图。「对比两家营收，再对管理层口径，再出带条款的结论」才上图。
- **怎么证明比开放 SQL 好？** 用失败 case，不用框架清单：比亚迪致辞「研发投入约 542 亿」vs 报表研发费用 531.9 亿（见 [BUG_NOTES.md](./BUG_NOTES.md)）；美的/格力/三一「营业收入 vs 营业总收入」G1 进 `human_review`。开放 SQL 容易给出「一个数」；我们应给出「不能当同一个数」。没有两种方案的 A/B 准确率，就不要说「我们更准」。

**踩坑：**

- 简历写成「自研金融 Agent 超越 NL2SQL」——改成「对比过开放 Text2SQL 与受控事实查询，年报数字采用后者」。
- 说「线上已经是 Agent 图、和他们打过 A/B」——用户面已合成一个助手，`app/agents/` 未接线时会被追穿。
- 为了「有 Agent」去复刻长链 NL2SQL，和 Q37 的取舍打架。

### Q39：W4 问数和 W6 Agent 怎么编排？Agent 挂哪些工具？

**30 秒答：** 编排分层，不把问数做成产品级 Agent。用户面只有一个助手（`/` / `POST /chat`）：规则路由寒暄 / 问数 / RAG，不先上 LangGraph。问数 = 公司 + 标准 concept + 期间，参数化查 `fin_metric`；槽位不全就反问。W6 图在**同一入口**里按任务拉起：拆步 → 调工具 → 数字校验 → 结构化结论，不另开对话页。工具共用 `lookup_metric` / RAG，不为 Agent 再写第二套检索。

**路由优先级（W4 接到 `/chat` 后）：**

1. 寒暄 → 现有 `_CHITCHAT_RE`
2. 问数 → 能抽出公司 + concept，且问「是多少」（不是「为什么 / 怎么样 / 是否合规」）；口语「赚了多少钱」算净利润，「今年/去年」锚在默认报告期。ROE / 毛利率 / 同比不回落 RAG 猜数；答数带 `[1]` 事实库引用，0 token
3. RAG → 因果、制度、叙述
4. 槽位不全 → 反问，不开放查全库

**W6 必挂工具（只读、一事一工具）：**

| 工具 | 作用 | 接到哪 | 硬约束 |
|---|---|---|---|
| `lookup_metric` | 公司/指标/年/口径取数 | W4 / `fin_metric` | 只 `auto_accepted`；没有或待复核就报缺口 |
| `rag_search` | 叙述检索 + 页码引用 | `prepare_chat_rag` | 低分拒答；必须有 `doc_id` + `page` |
| `verify_number` | 把声称的数字对回事实表 | 与质量门同一套 fact | 对不上就标冲突并停 |
| `list_scope` | 库里有哪家、哪年、哪些 concept | `fin_metric` + 年报 `doc_id` | 避免对未入库公司硬问 |
| `emit_conclusion` | 合规结论 DTO | `ComplianceConclusion` | 条款至少一条；高风险不准 confidence>0.95 |

**不挂：** `execute_sql`、手算 ROE/研发强度、写 `fin_metric`、联网补数。maker-checker 提交是 **W7 Java**；W6 最多 `escalate` 占位。W5 要点：工具合同稳定，先 Function Calling，以后 MCP 只换传输；Java 只暴露要鉴权/审计的动作，不把 RAG 再包一层。

**项目证据：** `api/chat.py` · `rag/service.py` · `rag/company_scope.py` · `schemas/compliance.py` · 用户面只有 `/`（`/agent` 重定向）；`app/agents/` 未接线，勿说图已上线

**追问准备：** 「对比两家营收」第一刀可以问数模块内两次 `lookup_metric`，不必上图；「对比 + 找管理层解释 + 出结论」才是 W6。评测看工具轨迹（该查数的有没有调 `lookup_metric`、冲突有没有放行），不看最终段落好不好看。Agent 黄金集未做之前，用质量门 + RAG 拒答当证据。

**踩坑：** `AgentView` 对照表把「比亚迪 2024 营收多少」写成 RAG——口述应改成问数。金融 Agent 场景是合规审阅/底稿/对比稿，不是自动出具合规意见或下单。

## 八、标准生产日志（目标架构）

> W1 现状见 Q27–Q31；本节是 **上线目标**，面试可说「现在做到哪、还缺什么」。

### 分层架构

```text
应用 logger（JSON + request_id + job_id）
    → stdout/stderr（容器标准输出）
    → 采集（Promtail / Fluent Bit / 云厂商 agent）
    → 存储检索（Loki / ELK / CloudWatch）
    → 仪表盘 + ERROR 率告警
```

**原则：** 生产 **不在容器里堆大 log 文件**；本地开发可加 `RotatingFileHandler` 方便排查。

### W1 现状 vs 目标

| 项 | W1 现状 | 标准生产 |
|----|---------|----------|
| 输出 | `StreamHandler(stderr)` 文本 | stdout **JSON** |
| 写文件 | ❌ | 本地可选轮转；生产靠平台 |
| 格式 | `%(asctime)s %(levelname)s [%(name)s] %(message)s` | 结构化字段可检索 |
| request_id | ❌ | ✅ 全链路（Java→Python） |
| ingest job_id | parser 已打 file 名 | ✅ 对接「解析监控」页 |
| Access vs App | uvicorn 访问日志 + app 业务日志分开 | 同上，网关/access 独立索引 |

### 日志级别约定

| 级别 | 用途 | 例子 |
|------|------|------|
| DEBUG | 开发调试，生产关 | 请求 body 片段 |
| INFO | 正常里程碑 | `POST /chat ok`、parse 完成 |
| WARNING | 可恢复 | 429 重试、降级 |
| ERROR | 需关注 | 超时、401、解析失败 |

### 每条日志建议字段

`timestamp` · `level` · `logger` · `message` · `service=regops-python-ai` · **`request_id`** · **`ingest_job_id`**（ingest 时）· `latency_ms`

**禁止：** API Key、完整 Cookie、未脱敏 PII。

### 与 RegOps 前端菜单

| 页面 | 日志来源 |
|------|----------|
| 日志监控 | 聚合 `app.*` + uvicorn + 以后 java-service |
| 解析监控 | `app.ingest.parser` + `ingest_job` 表 |
| 审计追踪 | audit 表 + correlation_id（不只文本 log） |

### 演进路线

```text
W1  logging 树 + stderr 文本（已完成）
W2  ingest 日志带 job_id；错误进 ingest_job 表
W3+ request_id 中间件；JSON 格式（structlog / python-json-logger）
上线 stdout → Docker → Loki/ELK；ERROR 告警
W9  Langfuse Trace（模型调用可观测，与文本 log 互补）
```

**项目证据：** `logging_config.py` · `web/` 菜单「日志监控 / 解析监控」占位 · W9 Compose/K8s
